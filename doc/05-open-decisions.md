# 05. 결정 사항 기록

아래 항목들은 구현 시작 전 사용자와 함께 확정한 내용이다. 새로운 미결정 사항이 생기면 이 문서에 추가하고, 확정되는 대로 표에 반영한 뒤 관련 문서(01~04)에도 옮겨 적는다.

| 항목 | 결정 | 비고 |
|---|---|---|
| 프로젝트/솔루션/앱 이름 | ~~`MakeFolder`~~ → **`folder-manage`(`FolderManage`)로 변경됨** | 처음엔 폴더명(`make-folder`)에서 유추했으나 여러 기능을 담는 앱이 되어 바꿨다 → 아래 "확정된 탭 구조 방향"의 "앱 이름" |
| 자리수 < 1 입력 시 | 오류로 처리 | 0이나 음수는 의미가 없으므로 |
| 생성할 폴더 개수가 매우 많을 때(예: 1000개 초과) | 확인 팝업 표시 후 진행 | **미리보기 단계와 생성 단계 모두** 동일하게 적용 → [doc/03-folder-naming-spec.md](03-folder-naming-spec.md) |
| 입력값 변경 시 미리보기 자동 갱신 여부 | 버튼을 눌러야 갱신(수동) | 매 입력마다 재계산하는 것보다 단순 |
| 폴더 생성 실패(권한 등) 시 처리 | 실패 항목만 건너뛰고 나머지 계속 진행, 마지막에 실패 목록 표시 | 하나 실패했다고 전체 중단하지 않음 |
| 문자(a,b,c...)/날짜 시퀀스 지원 여부 | v1 범위 밖, 필요 시 v2에서 추가 | [doc/01-overview.md](01-overview.md) 참고 |
| 생성 이력 저장 여부 | v1에서는 저장하지 않음 | 필요해지면 JSON 로그 추가 검토 |
| 접두사/접미사에 폴더명으로 쓸 수 없는 문자(`\ / : * ? " < > \|`) 입력 시 | 자동 제거/치환하지 않고 입력 자체를 오류로 거부 | → [doc/03-folder-naming-spec.md](03-folder-naming-spec.md) |
| 같은 이름의 "폴더"가 아니라 "파일"이 이미 있을 때 | "충돌"로 별도 표시, 건너뜀 (단순 "이미 존재"와 구분) | → [doc/03-folder-naming-spec.md](03-folder-naming-spec.md) |
| 입력 기본값 | 접미사 `화`, 자리수 `1` (나머지는 시작 1 / 종료 10 / 증가 1) | 접미사 기본값은 처음 입력을 시도하면 자동 삭제 → [doc/04-ui-flow.md](04-ui-flow.md) |
| 자동 생성(빠진 번호 채우기)의 범위 | 기존 숫자 폴더의 최솟값 ~ 최댓값 | 시작/종료 입력란은 사용하지 않음 → [doc/03-folder-naming-spec.md](03-folder-naming-spec.md) |
| 자동 생성에 적용하는 증가 단위·자리수·접두사·접미사 | 현재 입력란 값 그대로 | 기존 폴더의 패딩에서 자리수를 추정하지 않음 (예: `01화`가 있으면 자리수를 2로 직접 지정) |
| 자동 생성 시 미리보기/확인 | 미리보기 없이 바로 생성 (범위가 1000개 초과일 때만 확인 팝업) | 빈 폴더만 만들고 기존 항목을 지우거나 덮어쓰지 않으므로 |

위 표의 항목은 모두 **탭 1(폴더 만들기)** 기능에 대한 결정이다. 탭 구조 자체에 대한 결정은 아래 "현재 미결정 항목"에 있다.

## 확정된 탭 구조 방향

| 항목 | 결정 | 비고 |
|---|---|---|
| 메인 윈도우 형태 | 탭 구조 (탭은 기능 단위로 나눈다) | → [doc/06-main-window-tabs.md](06-main-window-tabs.md) |
| 지금까지 만든 make-folder 기능 | 탭 중 하나(탭 1)의 기능이 된다 | |
| 탭 1 | 이름 `폴더 만들기`, 기능은 기존 make-folder 기능(앱의 이전 이름) 그대로 | 사용자가 확정 |
| 탭 2 | 이름 `이미지 파일 이름 변경`, 기능은 폴더·파일의 공통 이름을 함께 바꾸는 것 | 사용자가 개요를 설명하고, 탭 이름은 Claude의 제안("변경"만으로는 내용을 바꾸는 것처럼 읽힘)을 채택 → [doc/07-image-rename-spec.md](07-image-rename-spec.md). 세부 규칙은 아래 "탭 2 미결정 항목" |
| 탭 순서 | 탭 1, 탭 2 순서 | 사용자가 번호를 붙여 설명 |
| 앱 이름 | **`folder-manage`** (코드/솔루션/exe 표기는 `FolderManage`) | 사용자가 제안하고 Claude가 동의. 여러 기능을 담는 앱이 되었고, `image-readers` 등 형제 프로젝트의 kebab-case 이름 형식과도 맞는다. **이름 변경 작업은 완료**(2026-09-19): 솔루션·프로젝트·네임스페이스·테스트 프로젝트·exe·아이콘 원본 파일명·창 제목을 바꿨고, GitHub 저장소도 `folder-manage`로 바뀌어 `origin`이 연결되어 있다. 로컬 작업 폴더 이름만 남았다 → [doc/06-main-window-tabs.md](06-main-window-tabs.md) "앱 이름 변경" |
| 탭 2: 접미사(`.debug`, `.debug-result`) 위치 | 확장자 **앞** (`001.debug.png`) | 사용자가 확정. 폴더 이름에도 붙는지는 아래 미결정 #1 |
| 탭 2: 새 이름 지정 방식 | 번호 규칙을 쓰지 않고 **사용자가 새 이름을 직접 입력** | 사용자가 확정. 한 번에 몇 개 그룹을 바꾸는지는 아래 미결정 #2 |

## 현재 미결정 항목

사용자와 함께 확정한다(그 전까지는 임의로 확정하지 않는다). 아래 "제안"은 기본값 후보일 뿐이다.

### 앱 전체

| 항목 | 제안 | 비고 |
|---|---|---|
| 탭 3 이후의 이름·기능·개수 | (없음 — 있다면 사용자 설명 대기) | 설명을 받으면 [06-main-window-tabs.md](06-main-window-tabs.md) 탭 목록과 탭별 문서를 채운다 |
| 로컬 작업 폴더 이름 | 사용자가 직접 `folder-manage`로 변경 (아직 `e:\code\make-folder`) | 코드 이름 변경이 끝났으므로 이제 진행할 수 있다. 폴더 이름을 바꾸면 Claude Code 세션 경로가 바뀌므로 변경 후 새 세션으로 시작한다 |
| 시작 시 선택되는 탭 | 첫 번째 탭 | 마지막에 쓰던 탭 기억은 하지 않음 |
| 탭 구성 방식 | 앱에 정해진 고정 탭 | 사용자가 탭을 추가·삭제·순서 변경하지 않음 |
| 탭 전환 시 상태 | 각 탭의 입력값·결과 유지 | [06-main-window-tabs.md](06-main-window-tabs.md) 공통 규칙 2와 같음 |
| 코드 폴더 구조 | 기능(탭)별 폴더(예: `Features/MakeFolder/`, `Features/ImageRename/`, 각각 `{Models,Services,ViewModels,Views}`)로 나누고, 여러 탭이 함께 쓰는 것(`IDialogService`, 이름 검증 등)은 `Common/` | 탭이 2개가 되어 결정 시점이 됨. 지금 코드는 계층별(Models/Services/ViewModels/Views) |
| 이름 검증 공용화 | 금지 문자 검사 등 폴더/파일 이름 규칙을 탭 1·2가 함께 쓰는 공용 서비스로 뽑음 | 현재는 탭 1의 `FolderNameGenerator.Validate` 안에 있음 |
| 창 크기 | 현재 크기 유지 | 탭 2 화면 설계 후 더 큰 화면이 필요하면 조정 |

### 탭 2 미결정 항목 (이미지 파일 이름 변경)

세부 내용은 [doc/07-image-rename-spec.md](07-image-rename-spec.md). 사용자 개요에서 해석이 갈리는 부분을 질문으로 정리했다. (접미사가 파일에서는 확장자 앞이라는 것과 새 이름을 사용자가 직접 입력한다는 것은 위에서 확정됨.)

| # | 질문 | 제안 |
|---|---|---|
| 1 | **폴더** 이름에도 `.debug`/`.debug-result` 접미사가 붙나? (폴더는 확장자가 없다) | 붙는 경우도 파일과 같은 규칙으로 접미사를 뗀다 |
| 2 | 새 이름을 직접 입력하는 방식에서, 한 번에 그룹 하나만 바꾸나(목록에서 그룹 선택 → 새 이름 입력 → 미리보기 → 변경), 아니면 목록의 여러 그룹마다 새 이름 칸을 두고 한꺼번에 바꾸나? | 그룹 하나씩. 여러 그룹 일괄이 필요해지면 그때 추가(이름이 서로 밀리는 경우 처리가 필요해져 복잡해짐) |
| 3 | 대상 폴더는 어떻게 정하나? 그 바로 아래만 보나, 하위 폴더 안쪽까지 재귀로 보나? | 폴더 선택 창으로 고르고, 바로 아래만 (재귀 X) |
| 4 | 폴더만 있거나 파일만 있는 "짝 없는" 이름도 변경 대상인가? | 대상에 포함하고, 목록에 "짝 없음"으로 표시 |
| 5 | 대상 파일을 이미지 확장자(png/jpg/webp 등)로 제한하나, 모든 파일인가? | 제한하지 않음(모든 파일). 이름 그대로 "이미지" 전용이면 필터 추가 |
| 6 | 접미사가 `.debug`, `.debug-result` 두 가지뿐인가? 앞으로 늘어나나? | 바꿀 수 있는 목록으로 두고 기본 2개 |
| 7 | 새 이름이 이미 있는 이름과 겹치거나 변경 도중 실패하면? | 그 그룹은 건너뛰고(충돌), 도중 실패하면 그 그룹은 원상 복구 — [07](07-image-rename-spec.md) 안전 규칙 |
| 8 | 미리보기 후 실행하나, 바로 바꾸나? | 미리보기 후 실행 (탭 1과 동일) |
| 9 | 이름 변경 되돌리기(undo)나 변경 이력 기록이 필요한가? | 직전 변경 되돌리기 또는 이력 파일 (이름 변경은 기존 항목을 건드리므로) |
| 10 | 한 번에 바꾸는 그룹이 많을 때 확인 창(탭 1의 1000개 기준)이 필요한가? | 탭 1과 같은 기준 적용 |

구현을 시작하려면 사용자의 명시적인 지시가 필요하다 ([CLAUDE.md](../CLAUDE.md) "개발 단계" 참고).
