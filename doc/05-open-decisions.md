# 05. 결정 사항 기록

아래 항목들은 구현 시작 전 사용자와 함께 확정한 내용이다. 새로운 미결정 사항이 생기면 이 문서에 추가하고, 확정되는 대로 표에 반영한 뒤 관련 문서(01~07)에도 옮겨 적는다.

| 항목 | 결정 | 비고 |
|---|---|---|
| 프로젝트/솔루션/앱 이름 | ~~`MakeFolder`~~ → **`folder-manage`(`FolderManage`)로 변경됨** | 처음엔 폴더명(`make-folder`)에서 유추했으나 여러 기능을 담는 앱이 되어 바꿨다 → 아래 "확정된 탭 구조 방향"의 "앱 이름" |
| 자리수 < 1 입력 시 | 오류로 처리 | 0이나 음수는 의미가 없으므로 |
| 생성할 폴더 개수가 매우 많을 때(예: 1000개 초과) | 확인 팝업 표시 후 진행 | **미리보기 단계와 생성 단계 모두** 동일하게 적용 → [doc/03-folder-naming-spec.md](03-folder-naming-spec.md) |
| 입력값 변경 시 미리보기 자동 갱신 여부 | 버튼을 눌러야 갱신(수동) | 매 입력마다 재계산하는 것보다 단순 |
| 폴더 생성 실패(권한 등) 시 처리 | 실패 항목만 건너뛰고 나머지 계속 진행, 결과 요약에 `실패 N개`를 표시 | 하나 실패했다고 전체 중단하지 않음. 처음엔 "실패 목록 표시"로 정했으나 현재 코드는 개수만 보여준다 → 아래 "탭 1 개선 후보" |
| 문자(a,b,c...)/날짜 시퀀스 지원 여부 | v1 범위 밖, 필요 시 v2에서 추가 | [doc/01-overview.md](01-overview.md) 참고 |
| 생성 이력 저장 여부 | v1에서는 저장하지 않음 | 필요해지면 JSON 로그 추가 검토 |
| 접두사/접미사에 폴더명으로 쓸 수 없는 문자(`\ / : * ? " < > \|`) 입력 시 | 자동 제거/치환하지 않고 입력 자체를 오류로 거부 | → [doc/03-folder-naming-spec.md](03-folder-naming-spec.md) |
| 같은 이름의 "폴더"가 아니라 "파일"이 이미 있을 때 | "충돌"로 별도 표시, 건너뜀 (단순 "이미 존재"와 구분) | → [doc/03-folder-naming-spec.md](03-folder-naming-spec.md) |
| 입력 기본값 | 접미사 `화`, 자리수 `1` (나머지는 시작 1 / 종료 10 / 증가 1) | 접미사 기본값은 처음 입력을 시도하면 자동 삭제 → [doc/04-ui-flow.md](04-ui-flow.md) |
| 자동 생성(빠진 번호 채우기)의 범위 | 기존 숫자 폴더의 최솟값 ~ 최댓값 | 시작/종료 입력란은 사용하지 않음 → [doc/03-folder-naming-spec.md](03-folder-naming-spec.md) |
| 자동 생성에 적용하는 증가 단위·자리수·접두사·접미사 | 현재 입력란 값 그대로 | 기존 폴더의 패딩에서 자리수를 추정하지 않음 (예: `01화`가 있으면 자리수를 2로 직접 지정) |
| 자동 생성 시 미리보기/확인 | 미리보기 없이 바로 생성 (범위가 1000개 초과일 때만 확인 팝업) | 빈 폴더만 만들고 기존 항목을 지우거나 덮어쓰지 않으므로 |

위 표의 항목은 모두 **탭 1(폴더 만들기)** 기능에 대한 결정이다. 탭 구조 자체에 대한 결정은 아래 "현재 미결정 항목"에 있다.

## 확정된 탭 구조 방향

| 항목 | 결정 | 비고 |
|---|---|---|
| 메인 윈도우 형태 | 탭 구조 (탭은 기능 단위로 나눈다) | → [doc/06-main-window-tabs.md](06-main-window-tabs.md) |
| 지금까지 만든 make-folder 기능 | 탭 중 하나(탭 1)의 기능이 된다 | |
| 탭 1 | 이름 `폴더 만들기`, 기능은 기존 make-folder 기능(앱의 이전 이름) 그대로 | 사용자가 확정 |
| 탭 2 | 이름 `이미지 파일 이름 변경`, 기능은 폴더·파일의 공통 이름을 함께 바꾸는 것 | 사용자가 개요를 설명하고, 탭 이름은 Claude의 제안("변경"만으로는 내용을 바꾸는 것처럼 읽힘)을 채택. "이미지"는 개념일 뿐 파일 종류 제한 없음 → [doc/07-image-rename-spec.md](07-image-rename-spec.md). 남은 세부는 아래 "탭 2 남은 세부 항목" |
| 탭 순서 | 탭 1, 탭 2 순서 | 사용자가 번호를 붙여 설명 |
| 앱 이름 | **`folder-manage`** (코드/솔루션/exe 표기는 `FolderManage`) | 사용자가 제안하고 Claude가 동의. 여러 기능을 담는 앱이 되었고, `image-readers` 등 형제 프로젝트의 kebab-case 이름 형식과도 맞는다. **이름 변경 작업은 완료**(2026-09-19): 솔루션·프로젝트·네임스페이스·테스트 프로젝트·exe·아이콘 원본 파일명·창 제목을 바꿨고, GitHub 저장소도 `folder-manage`로 바뀌어 `origin`이 연결되어 있다. 로컬 작업 폴더도 `e:\code\folder-manage`로 바뀌어(2026-09-19) 이름 변경은 전부 끝났다 → [doc/06-main-window-tabs.md](06-main-window-tabs.md) "앱 이름 변경" |
| 탭 2: 접미사(`.debug`, `.debug-result`) 위치 | 확장자 **앞** (`001.debug.png`) | 사용자가 확정. **폴더 이름에는 접미사가 붙지 않는다**(파일에만 적용) |
| 탭 2: 새 이름 지정 방식 | 번호 규칙을 쓰지 않고 **사용자가 새 이름을 직접 입력** | 사용자가 확정 |
| 탭 2: 변경 단위 | **그룹 하나씩** 변경. 순차적 변경·일괄 변경 요구 없음 | 사용자가 확정(2026-09-19). 이름이 서로 밀리는 경우의 처리는 필요 없다 |
| 탭 2: 대상 범위 | 대상 폴더 **바로 아래만**(재귀 X). 파일 종류 제한 없음 | 사용자가 확정 |
| 탭 2: 그룹 구성 | 폴더·파일·접미사 붙은 파일이 다 같이 있지 않아도 된다. **한 그룹에 실제로 있는 것만** 변경 | 사용자가 확정. "짝 없음" 표시는 필수가 아니다 |
| 탭 2: 접미사 목록 | 바꿀 수 있는 목록(기본 `.debug`, `.debug-result`), 추후 추가·삭제 가능 | 사용자가 확정. 관리 화면·저장 위치는 아래 "남은 세부" b |
| 탭 2: 이름 충돌 | 변경 **전에** 같은 이름이 있는지 검사해 결과를 알리고, 있으면 그 그룹은 **변경을 시도하지 않음** | 사용자가 확정 |
| 탭 2: 실행 흐름 | 미리보기 후 실행 (탭 1과 동일) | 사용자가 확정 |
| 탭 2: 되돌리기 | 되돌리기 기능을 구현한다 | 사용자가 확정. 범위·기록 보존은 아래 "남은 세부" a |
| 탭 2: 대량 변경 확인 창 | 지금은 필요 없음, 추후 선택 | 사용자가 확정 |
| 코드 폴더 구조 | **기능(탭)별 폴더**: `Features/MakeFolder/`, `Features/ImageRename/`, 공용은 `Common/`. 기능 폴더 안은 계층별 하위 폴더 없이 한 폴더 | 탭 2 구현 시(2026-09-20) 제안대로 적용. 사용자는 별다른 이의 없이 구현을 지시함 → [doc/02-architecture.md](02-architecture.md) |
| 이름 검증 공용화 | 금지 문자·새 이름 검증을 `Common/FileNameRules`로 뽑아 탭 1·2가 함께 쓴다 | 같은 시점에 적용. 탭 1의 동작·메시지는 그대로 |
| 창 크기 | 720×700(최소 600×560) | 탭 2 화면이 들어가도록 640×560에서 키움 |

## 현재 미결정 항목

사용자와 함께 확정한다(그 전까지는 임의로 확정하지 않는다). 아래 "제안"은 기본값 후보일 뿐이다.

### 앱 전체

| 항목 | 제안 | 비고 |
|---|---|---|
| 탭 3 이후의 이름·기능·개수 | (없음 — 있다면 사용자 설명 대기) | 설명을 받으면 [06-main-window-tabs.md](06-main-window-tabs.md) 탭 목록과 탭별 문서를 채운다 |
| 시작 시 선택되는 탭 | 첫 번째 탭 | 마지막에 쓰던 탭 기억은 하지 않음 |
| 탭 구성 방식 | 앱에 정해진 고정 탭 | 사용자가 탭을 추가·삭제·순서 변경하지 않음 |
| 탭 전환 시 상태 | 각 탭의 입력값·결과 유지 | [06-main-window-tabs.md](06-main-window-tabs.md) 공통 규칙 2와 같음 |

### 탭 1 개선 후보 (문서·코드 점검에서 발견, 미확정)

현재 코드의 동작이 문서의 원래 의도와 다르거나 문서에 없던 부분이다. 지금은 코드를 바꾸지 않았고 문서에 "현재 동작"으로만 적어 두었다.

| # | 내용 | 제안 |
|---|---|---|
| A | 미리보기·폴더 생성이 상위 폴더 존재 여부를 검사하지 않아, 경로를 잘못 입력하면 상위 폴더까지 통째로 새로 만들어진다 ([03](03-folder-naming-spec.md)) | 없는 폴더면 자동 생성과 같은 "상위 폴더를 찾을 수 없습니다." 오류로 막고, 상위 폴더는 자동으로 만들지 않는다 |
| B | 생성에 실패한 폴더의 이름과 사유가 화면에 표시되지 않고 개수만 나온다 | 실패한 항목을 미리보기 목록에서 "실패(사유)" 상태로 표시 |

### 탭 2 남은 세부 항목 (이미지 파일 이름 변경)

미결정 질문 10개는 사용자가 답해 확정했고(위 "확정된 탭 구조 방향"), 답변에 없던 세부는 아래 제안값으로 **구현했다**(2026-09-20). 다르게 하고 싶은 것이 있으면 알려 주면 바꾼다. 자세한 내용은 [doc/07-image-rename-spec.md](07-image-rename-spec.md).

| # | 항목 | 구현한 방식 |
|---|---|---|
| a | 되돌리기 범위 | 성공한 변경마다 기록해 가장 최근 것부터 하나씩 되돌림. 원래 이름이 이미 쓰이고 있거나 바뀐 항목이 없으면 되돌리지 않고 알림. 기록은 앱 실행 중에만 유지(종료하면 사라짐) |
| b | 접미사 목록 관리와 저장 | 화면에서 추가/삭제하고 `%AppData%\folder-manage\settings.json`에 저장(기본 `.debug`, `.debug-result`). 앱의 첫 저장 설정 |
| c | 변경 도중 일부만 실패하면(충돌 검사 통과 후) | 그 그룹은 이미 바꾼 항목을 원상 복구하고 실패로 알림 |
| d | 별도의 변경 이력 기록(파일) | 없음(되돌리기만) |
| e | 이름 규칙 세부 | [07](07-image-rename-spec.md)의 [제안] 표기대로: 마지막 점 뒤가 확장자, 긴 접미사 우선, 대소문자 무시, 대소문자만 바꾸면 임시 이름 경유, 금지·예약 이름 거부 |

새 기능(탭 3 이후, 탭 1 개선 후보 A·B 등)을 구현하려면 사용자의 명시적인 지시가 필요하다 ([CLAUDE.md](../CLAUDE.md) "개발 단계" 참고).
