# 07. 탭 2: 이미지 파일 이름 변경

> **상태: 규칙 확정(사용자 답변, 2026-09-19), 구현 완료(2026-09-20).** 표기: **[확정]** = 사용자가 정한 내용, **[제안]** = 사용자 답변이 없어 Claude가 채워 구현한 부분(다르게 하고 싶으면 알려 주면 바꾼다). 이 세부는 [05-open-decisions.md](05-open-decisions.md) "탭 2 남은 세부 항목"에 모아 두었다. 코드 구성은 [02-architecture.md](02-architecture.md) "탭 2 구성". 탭 구조는 [06-main-window-tabs.md](06-main-window-tabs.md) 참고.

## 목적 [확정]

어떤 폴더에는 폴더와 파일이 함께 들어 있고, 폴더와 파일은 (확장자를 뺀) 같은 이름을 갖는다. 이 "공통 이름"을 특정 이름으로 바꾸면, 같은 이름을 가진 폴더와 파일들이 모두 함께 새 이름으로 바뀌는 기능이다.

탭 이름의 "이미지"는 개념일 뿐이다. 이미지 파일로 제한하지 않으며 대상 파일은 전혀 다른 종류일 수 있다(확장자 필터 없음) **[확정]**.

## 용어

| 용어 | 뜻 |
|---|---|
| 대상 폴더 | 작업할 폴더. 그 **바로 아래**의 폴더와 파일만 대상이다(하위 폴더 안쪽은 보지 않음) **[확정]** |
| 접미사 | 파일 이름 끝(확장자 앞)에 붙는 `.debug` 또는 `.debug-result`. 있어도 같은 이름으로 판단한다 **[확정]**. 목록은 추후 추가/삭제될 수 있다 **[확정]** |
| 공통 이름 | 파일은 확장자와 접미사를 뺀 이름, 폴더는 이름 전체 |
| 이름 그룹 | 공통 이름이 같은 폴더와 파일들의 묶음. 폴더·파일·접미사 붙은 파일이 다 같이 있지 않아도 된다(폴더만, 파일만, 접미사 파일만도 한 그룹) **[확정]** |
| 새 이름 | 사용자가 지정하는, 그룹이 바뀔 공통 이름 |

## 공통 이름 판단 규칙

- **파일**: 확장자를 뺀 이름에서, 끝에 접미사 목록의 접미사가 있으면 그것도 뺀 이름이 공통 이름이다 **[확정]**. 접미사는 **확장자 앞**에 온다 **[확정]** (`001.debug.png`, `001.debug-result.png`).
- **폴더**: 폴더 이름에는 접미사가 붙지 않는다. 이름 전체가 공통 이름이다 **[확정]**. (그래서 `v1.2`처럼 점이 들어간 폴더 이름도 확장자로 오인하지 않는다.)
- 파일의 확장자는 **마지막 점 뒤**만이다(`001.v2.png`의 확장자는 `.png`, 공통 이름은 `001.v2`) **[제안]**. 확장자가 없는 파일이나 `.gitignore`처럼 점으로 시작하는 파일은 이름 전체를 확장자 없는 이름으로 본다 **[제안]**.
- 접미사 중 다른 접미사로 끝나는 것이 있으면(예: `.result`와 `.debug-result`) 더 긴 접미사를 먼저 뗀다 **[제안]**.
- 접미사 목록은 코드에 박아 넣지 않고 바꿀 수 있는 목록으로 둔다(기본 2개) **[확정]**. 화면에서의 관리 방식과 저장 위치는 [05-open-decisions.md](05-open-decisions.md) 참고.
- 이름 비교는 대소문자를 구분하지 않는다(Windows 파일 시스템과 동일) **[제안]**.

예 (대상 폴더 안):

| 항목 | 종류 | 공통 이름 |
|---|---|---|
| `001` | 폴더 | `001` |
| `001.png` | 파일 | `001` |
| `001.debug.png` | 파일 | `001` |
| `001.debug-result.png` | 파일 | `001` |
| `002` / `002.png` | 폴더 / 파일 | `002` (위와 다른 그룹) |
| `003.debug.png` | 파일 | `003` (이 파일만 있는 그룹, 이것만 변경 대상) |

## 이름 변경 동작

공통 이름을 새 이름으로 바꾸면 그룹에 **실제로 있는** 폴더·파일이 함께 바뀐다 **[확정]**. 새 이름은 **사용자가 직접 입력**한다 — 번호 규칙(접두사+번호+접미사 등)이나 순차적 변경은 쓰지 않는다 **[확정]**. **한 번에 그룹 하나씩** 바꾼다 **[확정]**. 각 항목의 접미사와 확장자는 그대로 유지하고 공통 이름 부분만 바뀐다 **[확정]**.

예: 그룹 `001`의 새 이름으로 `ch01`을 입력

| 변경 전 | 변경 후 |
|---|---|
| `001` (폴더) | `ch01` |
| `001.png` | `ch01.png` |
| `001.debug.png` | `ch01.debug.png` |
| `001.debug-result.png` | `ch01.debug-result.png` |

## 안전 규칙

파일 이름을 바꾸는 기능은 탭 1(폴더 생성)과 달리 기존 항목을 건드리므로 더 조심스럽게 다룬다.

1. **미리보기 후 실행**: 변경 전 → 변경 후 목록을 보여준 뒤 실행한다(탭 1과 같은 흐름) **[확정]**.
2. **변경 전 충돌 검사**: 실행 전에 바뀔 각 항목의 최종 이름과 같은 이름이 대상 폴더에 이미 있는지 검사하고, 그 결과를 사용자에게 알린다. 하나라도 이미 있으면 그 그룹은 **변경을 시도하지 않는다** **[확정]**. 그룹의 자기 자신은 충돌이 아니다(예: 대소문자만 바꾸는 경우). 그룹을 하나씩 바꾸므로 다른 그룹과의 이름 밀림·맞바꿈은 고려하지 않는다 **[확정]**.
3. **그룹 단위로 전부 성공 또는 전부 취소**: 충돌 검사를 통과해도 그룹 안 항목을 바꾸다 하나가 실패하면(파일이 사용 중 등) 이미 바꾼 항목을 원래대로 되돌려, 폴더와 파일 이름이 어긋난 상태를 남기지 않는다 **[제안]**.
4. **이름 검증**: 새 이름에 Windows 이름으로 쓸 수 없는 문자(`\ / : * ? " < > |`)가 있으면 거부한다(탭 1의 접두사/접미사 규칙과 동일). 빈 이름, 끝이 `.`/공백인 이름, 예약 이름(`CON`, `NUL` 등)도 거부한다 **[제안]**.
5. **대소문자만 바꾸는 경우**(`abc` → `ABC`): 같은 이름으로 오인해 충돌 처리하지 않고 임시 이름을 거쳐 바꾼다 **[제안]**.
6. **결과 요약**: 바뀐 항목 수와 실패(원복됨) 여부를 알린다 **[제안]**.

대량 변경 확인 창은 필요 없다(그룹 하나씩이라 한 번에 바뀌는 항목이 적음). 추후 필요해지면 그때 정한다 **[확정: 추후]**.

## 되돌리기 (기능 있음 [확정], 세부는 제안)

- 이름을 바꾼 결과를 되돌리는 기능을 구현한다 **[확정]**.
- 성공한 변경마다 (변경 전 경로 → 변경 후 경로) 목록을 기록하고, "되돌리기" 버튼이 **가장 최근 변경부터** 한 번에 하나씩 되돌린다 **[제안]**.
- 되돌릴 때도 충돌 검사를 한다: 원래 이름이 이미 다른 항목에 쓰이고 있거나 바뀐 항목이 없어졌으면(외부에서 바꾼 경우) 되돌리지 않고 이유를 알린다. 그룹 단위 전부 성공/전부 취소 규칙은 같다 **[제안]**.
- 기록은 앱을 실행하는 동안만 유지하고 종료하면 사라진다(이력 파일 저장 없음) **[제안]**. 되돌리기와 별도의 변경 이력 기록은 필요 여부를 정하지 않았다.

## 입력과 화면 (구현됨)

탭 1과 비슷한 흐름이다. 위에서부터 대상 폴더 줄, 접미사 목록, 그룹 목록, 새 이름 줄(버튼), 미리보기 목록, 상태 메시지 순이다.

1. 대상 폴더를 선택한다(경로 입력 + 찾아보기). 선택하면 바로 아래 항목을 읽어 **그룹 목록**(공통 이름과 그룹에 실제로 있는 항목)을 보여준다.
2. 목록에서 그룹 하나를 고르고 **새 이름**을 입력한다.
3. 미리보기: 변경 전 → 변경 후 목록과 충돌 검사 결과(신규 이름 / 이미 존재)를 보여준다.
4. "이름 변경"을 누르면 실행하고 결과 요약을 알린다. 그룹 목록은 새로 읽는다.
5. "되돌리기" 버튼으로 가장 최근 변경을 되돌린다.
6. 접미사 목록은 화면 위쪽에서 추가·삭제한다. 바꾸면 `%AppData%\folder-manage\settings.json`에 저장하고, 이미 읽은 폴더가 있으면 그룹을 다시 나눈다. 저장에 실패해도 그 실행 중에는 바뀐 목록으로 동작하고 실패 사유를 상태 메시지에 알린다.
7. 편의 동작: 그룹을 고르면 새 이름 칸에 현재 공통 이름이 채워진다. 새 이름 칸에서 Enter는 미리보기, 대상 폴더 칸에서 Enter는 새로고침이다. 새 이름·선택 그룹·대상 폴더를 바꾸면 미리보기가 지워지고 "이름 변경"이 다시 비활성화된다(미리보기를 거친 계획만 실행). 폴더 경로 칸을 고쳐도 "새로고침"/"찾아보기"로 다시 읽기 전까지는 마지막으로 읽은 폴더를 기준으로 동작한다.

번호 규칙은 쓰지 않으므로 탭 1의 시작/종료/증가/자리수/접두사·접미사 입력란에 해당하는 것은 없다 **[확정]**.

## 범위

- 대상 폴더 바로 아래 항목만 다룬다(재귀 X) **[확정]**.
- 이름만 바꾼다. 파일 내용, 폴더 위치(이동), 확장자는 바꾸지 않는다 **[제안]**.
- 파일 종류 제한 없음 **[확정]**.

## 사용자 원문 (탭 2 개요와 답변)

문서에 옮기면서 표현이 바뀌었을 수 있으므로 사용자가 한 말을 그대로 남긴다. 탭 이름은 처음 "이미지 파일 변경"이었으나 "이미지 파일 이름 변경"으로 바꿨다.

> 어떤 폴더에는 폴더와 파일이 있다. 폴더와 파일(확장자를 빼면) 같은 이름이 존재한다. 간혹 .debug or .debug-result 라는 접미사가 있지만 같은 이름으로 판단한다. 이 모든 폴더와 파일은 특정 이름으로 변경하면 파일과 폴더의 공통된 이름을 변경한다.

1차 답변:

- 접미사 위치는 확장자 앞이다.
- 이름 변경은 번호 규칙을 사용하지 않고 사용자가 임의로 입력하는 방식이다.

2차 답변 (2026-09-19, 미결정 질문 10개에 대한 답):

> 1. 폴더 이름에는 접미사 붙지 않는다.
> 2. 그룹 하나씩 변경, 이 이름 변경은 앞서 만든 순차적 변경등의 요구가 없음.
> 3. 대상폴더 바로 아래만 처리
> 4. 폴더와 파일 혹은 접미사가 붙은 파일이 다 같이 있지 않을 수 있음. 한 그룹에 있는 것만 변경.
> 5. 이미지 파일 이름을 변경하는게 아님. 개념만 이미지 파일이고 전혀 다른 파일일 수 있음.
> 6. 접미사는 추후에 추구되거나 삭제되거나 할 수 있음.
> 7. 변경하기 전에 같은 이름이 존재하는지 검사하고 그 결과를 알려줌. 같은 이름을 존재할 경우 변경시도를 하지 않음.
> 8. 미리보기 후 실행
> 9. 되돌리기 기능 구현
> 10. 추후 선택, 아직 필요없음.
